# T5 Outbox + Connection + confirm panel + Suggested tab

Part of `docs/specs/plugin-harness-local-proof.md`. Read it, the ADRs it lists and `GLOSSARY.md` first.

## What to build
Outbox: Proposals (`task.create|task.link|task.update|message.post`), dedupe key across reprocessing, states pending/confirmed/dismissed/retired (14 days), confirm only via an explicit API call from the UI, audit row with payload hash (no content), lockdown refuses confirm, state in DB. Connection: paste token into Keychain, retry/backoff, outbound policy check, no payload logging. UI in the current app: Proposal chip under each Action item, one right-side confirm panel with a 🔒 'what will be sent' line, To-dos › Suggested tab with nav count. Prove it with a fake test plugin.

## Done when
Host/HTTP tests with `FakeConnection`: no write without confirm, dedupe, retirement, lockdown refusal, audit hash only, Links recorded, disabled plugin has no effect, raising plugin isolated; automatic calls carry no recording text.
