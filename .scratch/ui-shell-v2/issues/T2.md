# T2 Surface contract endpoint and renderer

Part of `docs/specs/ui-shell-v2.md`. Read it, ADR 0005 (and 0002, 0004), `GLOSSARY.md` and design doc §13.10 first. Visual reference: `git show fab55e9:src/ui/web/prototype-plugins-ux.html`.

## What to build
Server: plugins declare contributions (catalog in the spec) next to `proposer`/`context_sources`; one read endpoint per context (app, recording, person, folder) returning contributions filtered for lockdown, plugin-excluded Recordings and disabled plugins; one action endpoint that runs a plugin's action handler. Notion and Slack declare their current UI as contributions (chips, links, selection action, Accounts rows, settings sections). Renderer: v2 components for annotation / action / panel kinds and the 'one chip + N' rule.

## Done when
HTTP tests (seam 1): contributions per context; empty when plugin off, under lockdown, for excluded Recordings; chip order and budget; action endpoint calls only the named plugin. Renderer fake-DOM test (seam 2) for each kind. Boundary test: v2 shell names no specific plugin.
